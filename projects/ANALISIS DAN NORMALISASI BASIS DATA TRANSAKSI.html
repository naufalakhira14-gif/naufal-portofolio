DATABASE DESIGN · FINTECH

BNPL Database Design & Normalization

A database design project focused on Buy Now Pay Later (BNPL) transactions in the Financial Technology (FinTech) industry. The project transforms an unnormalized transaction dataset into a structured relational database through normalization from UNF to Third Normal Form (3NF), aiming to reduce data redundancy and improve data consistency.

SQL ERD Database Normalization

01 / PROJECT OVERVIEW

Project Overview

This project focuses on designing a relational database for Buy Now Pay Later transactions. The initial transaction data is analyzed and normalized from Unnormalized Form (UNF) to Third Normal Form (3NF). The resulting database separates user, product, BNPL plan, transaction, and installment details into related tables to improve data organization and consistency.

05 / NORMALIZATION

From UNF to 3NF

Unnormalized Form (UNF)

The initial structure combines transaction information, BNPL plan attributes, and installment records, creating potential redundancy and data anomalies.

First Normal Form (1NF)

Organize the data into relational structures with atomic values and clearly defined records.

Second Normal Form (2NF)

Organize attributes to address partial dependencies on candidate keys where applicable.

Third Normal Form (3NF)

Separate entities and their attributes to address transitive dependencies and improve consistency.

Key Findings

01

02

Primary keys and relational references define the connections between users, transactions, products, BNPL plans, and installment payments.

The resulting database design provides a structured foundation for installment management and future analysis of overdue payments and repayment behavior.
